Kodra AI Agent is starting in {{ .Release.Namespace }}.

Check it:
  kubectl --namespace {{ .Release.Namespace }} rollout status deployment/{{ include "kodra-agent.fullname" . }}
  kubectl --namespace {{ .Release.Namespace }} logs deployment/{{ include "kodra-agent.fullname" . }}
{{- if .Values.console.enabled }}

Open the web console:
  kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "kodra-agent.fullname" . }}-console {{ .Values.console.port }}:{{ .Values.console.port }}
  then http://localhost:{{ .Values.console.port }}, signing in with KODRA_CONSOLE_TOKEN, or a console approver's own KODRA_CONSOLE_TOKEN_<NAME>, from the agent's Secret.
{{- if .Values.console.editSettings }}

Console approvers can change settings there. They are saved in the ConfigMap
{{ include "kodra-agent.fullname" . }}. Before a helm upgrade with a changed config, start from that copy:
  kubectl --namespace {{ .Release.Namespace }} get configmap {{ include "kodra-agent.fullname" . }} -o jsonpath='{.data.kodra-agent\.yaml}' > kodra-agent.yaml
{{- end }}
{{- end }}
{{- if not .Values.existingSecret }}

No existingSecret is set, so the agent has no secrets. Create them with
`kodra-agent init --target kubernetes` and set existingSecret.
{{- end }}
{{- if .Values.persistence.enabled | not }}

The audit log is on an emptyDir and is lost when the pod is replaced.
Set persistence.enabled=true to keep it.
{{- end }}
