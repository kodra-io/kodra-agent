# Audit, metrics, and tracing

Developer notes for working on the code. Moved from `CLAUDE.md`. User docs: `docs/observability.md`, `docs/security/`.

- Trust and observability (M14): see `docs/observability.md` and `docs/security/`. Audit records carry `seq` and `prev` (SHA-256 of the previous line, read from disk on every write, across rotation); `verifyAuditChain`/`auditHead` in `src/audit.ts`, `kodra-agent audit verify`, a doctor `audit chain` row; `spec.audit.stdout` writes records in `run`. `src/metrics.ts` (`AgentMetrics`) is fed by the AuditLog's `onRecord`, labels from fixed sets only (else `other`), served on `spec.metrics.port` (tests: `ctx.metricsPort: 0`). `src/tracing.ts`: OpenTelemetry, imported only when `spec.tracing.enabled`; `deps.tracer` spans `kodra.turn`/`kodra.model`/`kodra.tool`, no content; tests use `ctx.spanExporter`. Chart: metrics Service, optional ServiceMonitor and PrometheusRule from `files/alerts.yaml` (package test runs promtool on it); `dashboards/kodra-agent.json` (`src/dashboards.test.ts` checks metric names). Compose: only the one-shot `kodra-builder` (profile `build`) mounts the Docker socket. `docs/security/data-flow.md` carries a `id@fingerprint` per available manifest; `packages/connectors/src/data-flow.test.ts` fails when a manifest changes without it.
