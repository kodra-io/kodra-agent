# Evaluations and the demo

Developer notes for working on the code. User docs: `docs/evals.md`.

- Scenarios (L3): `evals/scenarios/<id>/` (`scenario.yaml`, `manifests.yaml`, optional `update.yaml`), loaded and validated by `src/evals/scenario.ts` (`SCENARIOS_DIR` resolves from the source file, so it works in the repo and in the image, which copies `evals/scenarios`). Every object must be in the namespace named after the scenario; `scenario.test.ts` pins the ten ids.
- `src/evals/cluster.ts`: kind through `Exec` (`createCluster` reuses one of that name; `internal` asks for kind's in-network kubeconfig), manifests by server-side apply with `KubernetesObjectApi` (no kubectl), `podMatches`/`waitReady`/`waitRollout`, and `agentKubeconfig`: a service account bound only by the bundle's read-only `rbacYaml`, with a TokenRequest token (registered with the redactor in `suite.ts`).
- `src/evals/investigate.ts`: `evalConfigYaml` (read-only Kubernetes connector, console off, placeholder approver), `triggerText` (alerts go through `investigationPrompt`), and `investigate`: the real runtime with `readOnly: true` (write tools are filtered out before the model sees them, which is why `mustNot` also has `says`). A closing `result` record per task flushes the audit queue before its records are read.
- `src/evals/checks.ts` (`judge`, `recommends` with sentence-level negation) and `report.ts` (`totalsOf`, `reportName`, `reportMarkdown`; cost via the manifest `pricing`, else unknown). `suite.ts` is shared by `scripts/eval.ts` (`pnpm eval`) and `src/commands/demo.ts`.
- Demo: `DEMO_SCENARIOS`, cluster `kodra-agent-demo`, refuses when `selfNames(env)` (inside the agent's pod); in a container (`/.dockerenv` or `KODRA_DEMO_INTERNAL=1`) it joins kind's Docker network by hostname. The image gets kind from `scripts/install-kind.ts` (pin in `src/evals/kind-pin.ts`, both arches). The Compose bundle has a `kodra-demo` service (profile `demo`). `scripts/package-test.ts` (`demoInImage`) runs it against a scripted OpenAI-compatible stand-in on the host (`host.docker.internal:host-gateway`); skip with `--no-demo`.
- The kind e2e test (`src/kind.e2e.test.ts`) keeps its own scripted crashloop in namespace `payments`; it is the CI integration test, not an evaluation.
