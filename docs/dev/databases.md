# Databases connector

Developer notes for working on the code. Moved from `CLAUDE.md`. User docs: `docs/connectors/databases.md`.

- Databases (`docs/connectors/databases.md`): a `builtin` runtime (`src/mcp/builtin.ts`, started by the host over `InMemoryTransport`, classified and guarded like any server). `src/databases/`: `health.ts` (fixed queries per engine via `mysql2`/`pg`, `judge` for ok/degraded/down, `failureReason` never passes driver text), `tunnel.ts` (`ssh2`, pinned host key fingerprint, the channel is the driver's socket), `server.ts` (`list_databases`, `database_health`). Settings use the `entries` field kind (`packages/schema/src/entries.ts`): named entries whose secrets must be `${env:<envPrefix><NAME>_<SUFFIX>}`; `components()` turns them into `SecretUse`s keyed `<name>.<field>`; the console writes the refs itself (`entriesWithRefs`), and so does the configurator (`entriesValue`; `ConnectorDraft.entries` holds the typed fields, never a secret, and `entrySecrets` names them for `.env.example`); `entrySecretWanted` decides which secrets an entry uses. `init` checks an entry's secret against that entry only, once its other secrets are known. `listValues` makes entries read like lists for guards and dashboard `forEach`. Probe `databases.connect` (`ProbeContext.only` tests one entry). `KODRA_DB_E2E=1` runs the real MariaDB/PostgreSQL tests.
