# Approvals, changes, and guardrails

Developer notes for working on the code. Moved from `CLAUDE.md`. User docs: `docs/approvals.md`, `docs/fixes.md`.

- Proposed changes (M9a): see `docs/fixes.md`. `src/changes.ts` (`propose_change`): every step through `decide()` first, one preview (diffs from `src/diff.ts`, files read by `src/forge-files.ts`), one approval, then the exact steps in order with a re-read before each file write. Which args hold repo/branch/path/content is the manifest's `changeSteps`. Audit details are clipped to 3,500 characters (the schema allows 4,000).
- Profiles and environments (M10): see `docs/approvals.md`. `resolvePolicy` (`packages/schema/src/policy.ts`) is the only place profile defaults live; `policyProblems` rejects rules nobody can satisfy. A call's environment comes from its guards (`touchedBy`: namespace guards with `scope: namespace`, and repo guards); one request covers one environment (`rulesFor`). Each `ApprovalRequest` carries a `Ballot`; Slack, the console, and the terminal vote through it. At runtime approvers are Slack user ids or `console:<name>` only; `init` turns `@name` into ids (`src/slack/names.ts`) and `doctor` flags any left.
- Change control (M11): see `docs/approvals.md`. Freezes (`packages/schema/src/freeze.ts`, local time per zone) turn writes into break-glass requests (`rulesFor` sets `freeze`; the ballot needs a reason; strict needs two). `requireChangeRef`/`changeRefPattern` make the first approval give a reference (Slack modal via `views.open`, console confirm step, terminal prompt), audited as `changeRef`. Console policy changes go through `PolicyGate` (`src/console/policy-gate.ts`). The `not-self` guard blocks writes to the agent's own objects (`KODRA_AGENT_SELF_*` from the chart); `src/self-protection.test.ts` classifies every write tool.
- Guardrails (M29): `src/credential-scope.ts` (`kubernetesScopeProblems` via `KubernetesClient.canI`, manifest `credentialScope`; refused in the probe and at startup unless `allowBroadCredentials`), `src/write-gate.ts` (`WriteGate`: `spec.limits.maxWritesPerHour`, seeded from the audit log, one change per environment; `deps.writes`, also in `propose_change`), `src/scale-limit.ts` (manifest `scaleLimit`: to zero or below half is destructive). Compose sets mem/cpu/pids limits and log rotation.
- After a change (M29b): `src/rollout.ts` (manifest `rolloutCheck`: `watchRollout` reads until `have` reaches `want`, `rollbackArgs`; `followRollout` in `agent.ts` runs in the background, audits, and `announce`s a change that did not settle; tests set `deps.rolloutTiming`). `src/checks/secret-health.ts` (`secretExpiry` for JWTs and kubeconfigs, age from audit and file times) feeds `secretFindings` in the agent check.
