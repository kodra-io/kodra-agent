# Sandbox tests

Developer notes for B2. User docs: `docs/sandbox.md`.

- Rules: `packages/connectors/src/kubernetes/sandbox.ts` (`SANDBOX_RULES`, `sandboxRulesYaml`, `NOT_A_SANDBOX`) feed the bundle's `rbacYaml` (only with read-write-approved access), the chart's `rbac.sandbox` Role (written out by hand; `bundle.test.ts` checks it matches), and the kubeconfig `sandbox` step. Settings `sandbox` and `sandboxPullSecret` are on the Kubernetes manifest.
- Agent: `apps/agent/src/sandbox/`. `sandbox.ts` has `sandboxSetup` (refuses a watched, own, default, or kube-* namespace, and read-only access), `sandboxDeploy`, `sandboxDestroy`, `sandboxSweep`, `sandboxList`. `helm.ts` runs Helm through `Context.exec` with `HELM_DRIVER=configmap`, the kubeconfig in a 0600 temp file as `KUBECONFIG`, EKS keys as `AWS_*`, and redacted output. `cluster.ts` is the `SandboxCluster` interface (placeholder ConfigMap, pods, services, proxy GET) with a `@kubernetes/client-node` implementation; tests pass `ctx.sandboxCluster` and `ctx.sandboxStableMs`. `state.ts` keeps `sandbox.json` next to the audit log, writes serialized.
- Ownership: a release is uninstalled only when it is in `sandbox.json` and `helm list --deployed --failed --pending --uninstalling -l kodra.io/owner=kodra-agent,kodra.io/agent=<name>,kodra.io/test=<id>` returns it. Helm 4 has no `--all`, and its JSON has no labels, so the selector is the check. Placeholder ConfigMaps are deleted by name, never by label: Helm's own record ConfigMaps carry the same labels. A test is destroyed in the namespace recorded with it (`destroyTest` refuses one that could not be a sandbox), so `cleanupSetup` keeps cleanup going after the setting is changed or cleared, with read-write-approved access; the left-over scan covers the current sandbox only. `run` sweeps when `sandboxCanClean`.
- Approval and limits: one request (`connector: kubernetes`, `tool: sandbox test`) with `rulesFor` on the sandbox namespace; the install takes a `WriteGate` slot and is audited `approved`. Uninstalls are audited `allowed` and never go through the gate, so cleanup is never refused.
- Clone and tag: `findSource`, `Git`, `remoteUrl` from ship. Tag is `<sha>` when the branch is the remote HEAD (`git ls-remote --symref origin HEAD`), else `pr-<sha>`; values are passed with `--set-string`. Smoke path from `analyzeRepo`'s detection.
- Surfaces: CLI `commands/sandbox.ts`; console jobs reuse `OnboardJobs` (kind `sandbox`, action `onboard/sandbox` with `keepMinutes`, `sandbox/destroy`, `onboard` returns `sandbox`); `run` sweeps at startup and every 5 minutes.
- Tests: `src/sandbox/sandbox.test.ts` (real git, fake Helm and cluster); `src/kind.e2e.test.ts` deploys a busybox httpd image built and loaded by `scripts/kind-test.ts`, checks the Role with `kubectl auth can-i`, and shows a forged list entry or an unlabeled `kt-*` release is left alone. The kind CI job installs Helm 4.3.0 for it.
