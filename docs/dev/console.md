# Console

Developer notes for working on the code. Moved from `CLAUDE.md`. User docs: `docs/console.md`.

- Console (M8): see `docs/console.md`. API in `apps/agent/src/console`: token sign-in (shared `KODRA_CONSOLE_TOKEN` views and chats; `console:<name>` approvers use `KODRA_CONSOLE_TOKEN_<NAME>`), POST actions need the session, Origin, and `x-kodra-console: 1`, chat events stream as SSE (`runTurn`'s `events` sink, never tool output). Approvals fan out (`fanOut`) to Slack and the console; first decision wins. The app in `apps/console` is tested against a mocked API. Usage cost comes from `pricing` in the model manifest or `spec.console.pricing`.
- Console settings (M8c): `src/console/settings.ts` patches kodra-agent.yaml with `yaml`'s Document API (comments stay), validates with `parseAgentConfig`, keeps `.previous`, audits `settings`, and restarts by exiting 75 (Compose restarts it). Secrets go to `.env` only after their probe passes. Console sessions are HMAC-signed cookies keyed by each account's token hash, so restarts keep sessions. Pause state is `control.json` next to the audit log; the budget is `spec.limits.monthlyBudgetUsd`.
- Console admin: `src/console/admin.ts`. No default password (L2): `init` asks for one (or reads `KODRA_CONSOLE_ADMIN_PASSWORD` with `--non-interactive`) and writes only `KODRA_CONSOLE_ADMIN_HASH` (`scrypt1:<setAt>:<salt>:<hash>`) to .env or the Secret; a console change writes `console-users.json` (with `setAt`) next to the audit log; the later one wins (`init --reset-console-password`). `run` exits 1 and `startConsoleServer` throws when none is set; doctor has an `admin password` row. Changing it re-keys the admin's sessions. Tests use `TEST_ADMIN_PASSWORD`/`TEST_ADMIN_HASH` from `test-helpers.ts`. `isTokenApprover` (schema) is every console approver but `console:admin`, which needs no token. Tokens still sign in. Full user accounts come later.
- Dashboard: `src/dashboard.ts` (`ConnectorDashboard`, route `dashboard`). Manifests list cards (`dashboard`: a read tool, `forEach` over a list setting, and a generic view `pods`/`deployments`/`events`/`runs`); calls go through `decide()` and the redactor, never the model, are cached 60 s, and are not audited. Readers are tested on recorded real output in `src/test-fixtures/dashboard`.
- Operations center: `apps/console/src/briefing.ts` (greeting by hour, `briefing` ranks the attention queue by severity and sets the posture, `totalsOf`/`systemsOf`/`runsToday` from the dashboard route; never the model), rendered by `welcome.tsx` on Overview in the console theme. `ask.ts` hands Chat a question to prefill (not send). Runs data carries `recent` (every listed run's time and state) and `full`, so the console counts today in the viewer's time zone. Databases: the Kubernetes `databases` setting (`namespace/name`) feeds a `workload` card (`forEach.scoped`: `arg` gets the namespace, `podOf` keeps the workload's pods).
- Setup from the console (M28): see `docs/console.md`. Manifest secrets and fields have `steps` (`packages/schema/src/steps.ts`: text, https or `{{url}}/` link, `run` as `all` or `linux`/`macos`/`windows` PowerShell); `{{setting}}` placeholders (`:comma` joins lists) are checked by the schema and filled by the agent (`fillSteps`; commands and links take only shell-safe values, else `<key>`). `format: kubeconfig | ssh-private-key` secrets are pasted or uploaded: `src/console/secret-files.ts` checks their shape, `SettingsStore.setSecret` probes, then saves a file in the bundle's `secrets/` (Compose, `ConfigBackend.writeSecretFile`) or the agent's Secret, and `setSecretRef` points the config at it. A registry test requires steps on every secret. Settings, Network takes trusted CA certificates (`SettingsStore.setCaBundle`, `caCertificates`; Compose only, saved as `ca/console-ca-bundle.pem`; route `settings/ca-bundle` takes up to 768 KB). Kubernetes has optional `KODRA_EKS_*` keys (one `group` in the configurator) for EKS exec kubeconfigs (`KubernetesFactory` passes `execEnv`).
- Everything in the console (M30b): `SettingsPatch` covers every section (`profile`, `environments` replaced whole, `checks`, `monitoring`, `network.noProxy`, `dataProtection`, `models`, `ship`, `metrics`, `tracing`, `audit`, approval rules, `limits.maxWritesPerHour`, connector `allowBroadCredentials`); `moreAccess` adds `broad`, `unmasked`, `named-model`, `tracing`. `SettingsStore.setProxy` (proxy URLs to .env as `KODRA_HTTPS_PROXY`/`KODRA_HTTP_PROXY`), `withSlackIds` (new `@name` approvers via `users.list`; tests set `slackBase`). Routes `settings/proxy`, `settings/doctor` (`doctorRows`), `settings/audit-verify`. Console editors in `settings-more.tsx`.
