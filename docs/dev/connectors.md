# Connectors and MCP servers

Developer notes for working on the code. Moved from `CLAUDE.md`. User docs: `docs/connectors/`.

- MCP servers: each connector manifest pins its server (binary SHA-256 or PyPI version), lists every tool with a risk, and declares args/env. The host starts each server in an empty private temp folder (some servers load `.env` from cwd) with a minimal env plus only that connector's secrets; secrets go in env or 0600 files, never argv. Classify tools from `listTools` on the real binary (`scripts/list-tools.ts`) and document the decision in `docs/connectors/<id>.md`.
- Manifest features beyond M4a: `runtime` can list several servers (named; tool names must not overlap); `{ secret|setting, from }` and guard `from` share another connector's values only if it is in `requires`; `hiddenTools` drops tools a server offers when it has no usable filter; guards `repo-in-setting` and `not-default-branch` (needs `defaultBranchLookup`). Server-side filters are best-effort (GitLab's deny regex silently fails open over 200 chars); the host's classification is the real gate. `KODRA_REAL_SERVERS=1` runs `src/real-servers.e2e.test.ts`, which fails if a pinned server offers an unclassified tool.
- Since 0.1.2: a connector that fails to start is skipped, not fatal (`host.failures()`, hints in `failureHint`). Secrets can be `requiredOn` one target (kubeconfig on compose); check with `isSecretRequired`. Tool descriptions list guard limits (`describeGuards`). `onlyIf` starts a server only when a list setting includes a value (no connector uses it since B4).
- Since B4: `riskFrom` gives a tool that runs any command it is given (AWS `call_aws`) a risk per call, read from its command (`callRisk` in `policy.ts`, `apps/agent/src/aws/cli-risk.ts`); the manifest classifies it `write`, and the agent passes each call's own risk to the audit log, approvals, and events. Regenerate `src/aws/read-operations.json` with `scripts/aws-read-operations.py` when the AWS server's pin moves (run it with the pinned server's venv Python). `accessEnv` sets environment variables per access level, like `READ_OPERATIONS_ONLY=true`. `retired: { config, secrets }` keeps a removed setting or secret loading after an upgrade (deprecated in the JSON Schema, ignored, and left out of "Allowed:" hints).
- Probe endpoints were checked against provider docs (Oct 2026): GitHub `GET /repos/{repo}` (fine-grained tokens), GitLab `/api/v4/projects/:path`, Slack `auth.test` + `apps.connections.open`, Anthropic `/v1/models`, Azure `{endpoint}/openai/v1/models` with `api-key`, Grafana `/api/org/` (service account tokens cannot use `/api/user`).
- Jenkins: `mcp-jenkins` 3.5.0 from PyPI (`docs/connectors/jenkins.md`); job tools are guarded by `jobs` with `arg-in-setting` `prefix` (`inList` in `policy.ts` refuses `..`, empty segments, `\` and `%`); Groovy, config.xml, and queue cancel are hidden. Dashboard `jobs` view maps a status word with `states` and filters by `scope`.
- Status (L1): `available` (stable), `preview`, or `coming-soon`. `isUsable` (schema) is the check for "can be enabled"; never test `status === 'available'` for that, or preview connectors drop out of config parsing, the data-flow test, and the secret-steps test. The configurator and console list preview connectors under "More connectors" with a badge; `registry.test.ts` pins which ids are which. No connector is in preview since B3 (Docker, Jenkins, and Databases became `available`).
